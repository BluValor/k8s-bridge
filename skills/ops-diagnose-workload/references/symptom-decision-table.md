# Symptom Decision Table & Exact Error Reference

## 1. End-to-End Troubleshooting Decision Table

| Observed Slurm Job State & Fields | Root Cause | Diagnostic Check / Next Step |
|---|---|---|
| Rejected client-side: `Validation error: job uses an option that is not supported by k8s-bridge (--<opt>)` or `(heterogeneous job pack_offset=<d>)` | CLI flag is not in `hack/cli_filter.lua` `ALLOWED_OPTIONS` (e.g. `--requeue`, `--nodelist`, `--constraint`, `--exclusive`, `--het-group`) or heterogeneous job (`pack_offset > 0`). | Remove the unsupported CLI flag from `srun`/`sbatch`/`salloc`, or update `hack/cli_filter.lua` via `dev-slurm-lua`. |
| Unsupported CLI flags (`--exclusive`, `--nodelist`, `--array`) accepted client-side on a bridged partition | Partition is missing from `CliFilterParameters=workload_mixing_partitions=...` in `slurm.conf`, or `deploy/slurm-login-slinky` has stale `/run/slurm/conf/slurm.conf` after `helm upgrade slurm`. | Compare `kubectl -n slurm exec deploy/slurm-login-slinky -c login -- grep CliFilterParameters /run/slurm/conf/slurm.conf` against `scontrol show config \| grep CliFilterParameters`; update `CliFilterParameters` or delete the login pod (`kubectl -n slurm delete pod -l app.kubernetes.io/name=login`) via `infra-configure-crs`. |
| `sbatch`/`squeue`/`scontrol` fails with `Unable to contact slurm controller (connect failure)` (`slurm-controller-0` `1/2 Ready`) | `slurmctld` is crash-looping (`job_submit/lua: Unable to stat /etc/slurm/job_submit.lua` when `helm upgrade slurm` omitted `--set-file`; other `fatal:` lines indicate `slurm.conf` syntax/plugin errors). | Check `kubectl -n slurm logs slurm-controller-0 -c slurmctld --previous --tail=50` (and current logs); re-run `helm upgrade slurm` with both `--set-file` Lua flags via `infra-configure-crs`. |
| Rejected by `slurmctld` (client: `Batch job submission failed: Unspecified error` or `Unspecified error for job <ID>`; `slurmctld` log in snapshot §6: `Multi-partition request '<parts>' contains workload mixing partition.` or `immutability rule`) | Multi-partition submission including a `WORKLOAD_MIXING_PARTITIONS` partition, or non-root job owner running `scontrol update/hold` on a bridged job (`immutability rule`). | Submit to a single partition (`--partition=<single-part>`), or cancel and resubmit with desired flags (or have an admin modify the job). |
| Rejected by `slurmctld`: `Invalid generic resource (gres) specification`, `More processors requested than permitted`, `Required partition not available (inactive or drain)`, or `User's group not permitted to use this partition` (no `JOB_ID`) | `Invalid generic resource`: `GresTypes` lacks `gpu`. `More processors requested than permitted`: `EnforcePartLimits=ALL` on a dynamic partition with 0 static nodes. `Required partition not available` / `group not permitted`: partition `State=DRAIN`/`INACTIVE` or `AllowGroups` restriction (`scontrol show partition <part>`). | Enable `GresTypes=gpu` and `EnforcePartLimits=NO` in `controller.extraConf` via `infra-configure-crs`, or check `scontrol show partition <part>` (report/confirm before changing admin partition policy; runtime `scontrol update` does not persist across `slurmctld` restarts). |
| `JobState=PENDING`, `Priority>0` (not held), or `JobState=CANCELLED`, `Comment="JobSet missing"` (`Reason!=JobHeldUser`, bridge logs `JobSet missing for active Slurm job, cancelling job`) | Partition is missing from `WORKLOAD_MIXING_PARTITIONS` on `slurmctld` (`job_submit.lua` never held the job: stays `PENDING` if unmapped in `WorkloadMixing`, or is cancelled with `JobSet missing` if mapped; also occurs if root ran `scontrol release` on an untranslated held job, or if the `JobSet`/`WorkloadMixing` CR was deleted out-of-band after translation). | Check `kubectl -n slurm exec slurm-controller-0 -c slurmctld -- printenv WORKLOAD_MIXING_PARTITIONS` and add partition to `controller.slurmctld.env` via `infra-configure-crs`. |
| `JobState=PENDING`, `Reason=JobHeldUser`, `Comment` lacks `k8s-bridge-auto-hold` | Job was submitted with `--hold`. `k8s-bridge` waits for the user to release the hold. | Run `runuser -u <user> -- scontrol release <JOB_ID>` (note: returns exit code 1 `ESLURM_REQUESTED_PART_CONFIG_UNAVAILABLE` when 0 dynamic nodes exist, but sets `k8s-bridge-auto-hold`). |
| `JobState=PENDING`, `Reason=JobHeldAdmin` | Administrator hold is active on the job. | Do **not** run `scontrol release <JOB_ID>` as root if `JobSet/slurm-job-<JOB_ID>` does not exist yet (root bypasses `job_submit.lua`, causing `SlurmJobReconciler` to cancel the job with `Comment="JobSet missing"`); only release as admin if the `JobSet` already exists. |
| `JobState=PENDING`, `Reason=JobHeldUser`, `Comment` contains `k8s-bridge-auto-hold` | `k8s-bridge` has not translated or unheld the job. | 1. Verify `WorkloadMixing` is `Available=True` (if `ControllerNotFound` or `RestApiNotFound`, align `spec.controllerRef.name` with `kubectl -n slurm get controller,restapi`; once `Available=True`, existing auto-held jobs translate automatically — do **not** `scontrol release` as root).<br>2. Verify partition is in `WorkloadMixing.spec.partitionsMapping`.<br>3. Inspect `k8s-bridge-controller-manager` logs for `slurmrestd` / JWT errors. |
| `JobState=RUNNING` (or `PENDING`) with `Features=(null)` while `k8s-bridge` logs `failed to release hold ... Invalid feature specification` | `SchedulerParameters=ignore_constraint_validation` is missing from `slurm.conf` (`controller.extraConf`): the hold is released before `k8s-id-<jobID>` feature validation fails, leaving the job unbound (may run on another job's node). | Check `scontrol show config \| grep SchedulerParameters` and restore `SchedulerParameters=ignore_constraint_validation` in `controller.extraConf` via `infra-configure-crs`. |
| `JobState=CANCELLED`, `Comment="Translation failed: ..."` (note: `Reason` still shows `JobHeldUser`) | `JobSetTranslator` rejected the job (missing GPU GRES mapping, invalid `NodeCount`, mixed GPU types, indivisible `TresPerJob`, or invalid `dynamicNodeFeature`). | Inspect `Comment` in `scontrol show job <JOB_ID>` and `kubectl -n slurm get events --field-selector reason=JobTranslationFailed`. Update `WorkloadMixing` via `infra-configure-crs`. |
| `JobState=PENDING`, `Comment` has `Unheld by k8s-bridge`, `JobSet` has `SUSPENDED=true` | Waiting for Kueue admission: quota/`lendingLimit` exhaustion (pod sizing in `translator.go`: `replicas = minNodes` [`--nodes=min-max` -> `minNodes` pods], `tasksPerNode = ntasksPerNode` or `ceil(ntasks/replicas)`, `podCPU = cpusPerTask*tasksPerNode` [`--ntasks` sets `cpusPerTask=1`, shadowing `--cpus-per-gpu`] or `cpusPerGpu*gpusPerPod` or `tasksPerNode`, `podMem = max(memPerNode, memPerCpu*podCPU, memPerGpu*gpusPerPod, 2048Mi*podCPU)` floor, plus any `podTemplate` sidecar requests; `--overcommit` ignored — use `sbatch -n1` with inner `srun -n<N> --overcommit`), `requests must not exceed its limits` (`podTemplate` static `limits` or `LimitRange` `default`/`max` `< 2048Mi*cpu` floor), `resource <X> unavailable in ClusterQueue` (extra `podTemplate` request like `ephemeral-storage` not in `ClusterQueue` `coveredResources`), `LocalQueue <name> doesn't exist` or `LocalQueue`/`ClusterQueue` is inactive (`stopPolicy`, `FlavorNotFound`, `AdmissionCheck*`, `Cohort` `parentName` cycle), `workload namespace doesn't match ClusterQueue selector`, `flavor <X> doesn't match node affinity` (`podTemplate.spec.nodeSelector` conflicts with `ResourceFlavor.nodeLabels`), `untolerated taint ... in flavor` (`podTemplate` tolerations lack `ResourceFlavor.nodeTaints`), or TAS `no topology domains at level`, `StrictFIFO` head-of-line blocker (newer `Workload` has empty `.status.conditions`), pending `status.admissionChecks` (`QuotaReserved=True`, `Admitted` absent), `Workload` has `Admitted=True` while `JobSet` stays `SUSPENDED=true` (`jobset-system` controller/webhook down; check `kubectl -n jobset-system get deploy,endpoints` and `kueue` logs), or no `Workload` exists (missing `WorkloadPriorityClass` or `JobSet` installed after `Kueue` without restart). | Run `kubectl -n slurm describe workload -l "kueue.x-k8s.io/job-uid=$(kubectl -n slurm get jobset slurm-job-<JOB_ID> -o jsonpath='{.metadata.uid}' 2>/dev/null)"` and check `kubectl get clusterqueue,localqueue -A -o jsonpath='{range .items[*]}{.kind}/{.metadata.name}: {.status.conditions}{"\n"}{end}'`. Report/confirm with user before altering admin queue policies (`queueingStrategy`, `admissionChecks`, `coveredResources`); if no `Workload` exists, check `kubectl get workloadpriorityclass` and `kueue-controller-manager` logs. |
| `JobState=PENDING`, `JobSet` has `SUSPENDED=false`, `slurmd` pods `< replicas` (`0` pods), `Pending`, `CrashLoopBackOff`, or `Running (0/1 Ready)` | `< replicas` pods: child `Job` `FailedCreate` or `JobSet` `JobCreationFailed` (`ResourceQuota` pod cap or required `limits`, `podTemplate` `requests > limits`, or missing `ServiceAccount`). `Pending`/`CrashLoopBackOff`/`Running (0/1 Ready)`: insufficient node resources (or per-node capacity fragmented by non-Kueue pods), missing GPU/DWS tolerations, `ImagePullBackOff` (`placeholder-image`), `slurmd` looping `_establish_configuration` retries (`0` restarts under `supervisord`) from missing `slurm.key`, custom `/etc/slurm` mount shadowing `slurm-etc`, or stale `--conf-server` arg, `Unable to add node, node table is full` in `slurmctld` logs (`MaxNodeCount` exhausted; `slurmd` silent, registers once at startup, probe-killed after ~300s), or registered `IDLE` node failing `startupProbe`/`livenessProbe` (`300s`/`60s` deadline) while waiting for sibling gang nodes or deferred `StartTime`/`BeginTime`. | Follow Step 2 Branch 7 (`describe jobset`, `describe job`, `describe pod`, `logs -c slurmd`, and `slurmctld` logs). If `Insufficient cpu/memory/gpu` (Kueue admits on aggregate quota, not single-node `allocatable`), reshape the job (`--nodes` / `--ntasks-per-node`) or report — never create/resize node pools or delete other tenants' workloads without user confirmation. |
| `JobState=PENDING` (`Reason=BadConstraints`, `Partition*`, `launch_failed_requeued_held`, or `Nodes required for job are DOWN`), `slurmd` pods `Running` (registered in `scontrol show nodes`) or gone | `WorkloadMixing.spec.partitionsMapping[].dynamicNodeFeature` does not match `NodeSet` `Feature` in `slurm.conf` (`TotalNodes=0` in `scontrol show partition`), stale dynamic nodes remain in `slurmctld`, or `scontrol show partition <part>` has `State=DOWN`, `AllowGroups`, or `MaxNodes`/`MaxCPUsPerNode`/`MaxMemPerNode`/`MaxTime` caps (`EnforcePartLimits=NO` defers checks until after dynamic pods register). | Compare `scontrol show node <node>` `ActiveFeatures` against `slurm.conf` `NodeSet`, clean up stale dynamic nodes via `ops-cleanup-state`, and inspect `scontrol show partition <part>` (reshape job or confirm before changing admin partition policy; permanent partition changes belong in `controller.extraConf`). |
| `JobState=FAILED` right after scheduling onto dynamic `slurmd` pod (e.g. `Reason=RaisedSignal:53` / `WTERMSIG 53` in ~1s) | `WorkDir`/`StdOut` directory (default: login submit cwd `/home/<user>`) does not exist on the dynamic `slurmd` pod, or `LD_LIBRARY_PATH` was overwritten by `srun` on a GPU job. | Pass `--chdir=/tmp` (or `-o /tmp/%j.out`, or mount a shared volume in `podTemplate`; note pod and local `StdOut` are deleted ~5s after job end) and `--export=ALL,LD_LIBRARY_PATH=/usr/local/nvidia/lib64` on GPU `srun` jobs (`infra-configure-crs`). |
| `JobState=CANCELLED`, `Comment="JobSet completed"`, `Restarts>=1` (or job never completed) | Dynamic `slurmd` pod was terminated gracefully (`kubectl delete pod`, eviction/drain) or killed by `startupProbe`/`livenessProbe` after sitting `IDLE`/`DOWN` >300s/60s (`scontrol requeue`, dynamic node `State=DOWN`, deferred `StartTime`, or incomplete gang): `supervisord` exited `0`, marking the `JobSet` `Completed` (`NotIn [0]`) and causing `k8s-bridge` to cancel the Slurm job. | Inspect pod/node events and `slurmctld` logs; avoid `scontrol requeue` or `StartTime` deferral on bridged jobs, and resubmit the job. |
| `JobSet` stuck in `Terminating` (`deletionTimestamp` set, `k8s-bridge.x-k8s.io/slurm-node-cleanup` finalizer present) | `k8s-bridge` was uninstalled before `JobSet` finalization completed, or `slurmrestd` is unreachable while Slinky `Controller` CR still exists. | If `k8s-bridge` is running, check `k8s-bridge-controller-manager` logs for `slurmrestd` errors; if `k8s-bridge` was uninstalled, remove `k8s-bridge.x-k8s.io/slurm-node-cleanup` via `ops-cleanup-state`. |
| Preempted or queue-stopped job (`Workload` `Evicted=True` with `Preempted` or `LocalQueueStopped`; `JobSet` `SUSPENDED=true` or deleted) | Kueue preempted the workload or `LocalQueue`/`ClusterQueue` transitioned to `HoldAndDrain`. | If `Requeue=1`: Slurm requeues (`PENDING`, `Reason=BeginTime`, `Restarts>=1`, `JobSet` `status.restarts=0`). If `--no-requeue`: Slurm marks `NODE_FAIL` (`Reason=NodeDown`, `Comment` unchanged) and `k8s-bridge` tears down the `JobSet`. |

## 2. Exact Translator & Controller Error Strings (`internal/controller/slurmjob/`)

| Source File | Error String | Meaning |
|---|---|---|
| `slurmjob_controller.go` / `translator.go` | `Multi-partition jobs with multiple mapped partitions are not supported` \| `multiple partitions specified with managed partition: <parts>` | Multi-partition job rejected by `newJobCheckMultiPartition` or `Translator.Translate`; job cancelled. |
| `translator.go` | `job NodeCount is unset` \| `invalid NodeCount: <n>` \| `infinite NodeCount is not supported` | Invalid `NodeCount` on `V0044JobInfo`; job cancelled. |
| `translator.go` | `missing GRES mapping for gpu:<type>` | Requested GPU type (or untyped `gpu:`) is missing from `WorkloadMixing.spec.mappedResources`; job cancelled. |
| `translator.go` | `multiple heterogeneous gpu requests are not supported: <details>` | Single job requested multiple distinct GPU types; job cancelled (adding `mappedResources` entries cannot enable multi-type GPU requests within one job). |
| `translator.go` | `TresPerJob gpu count (<n>) is not cleanly divisible by NodeCount (<m>)` | `--gpus` / `--gpus-per-job` cannot divide evenly across nodes; job cancelled. |
| `translator.go` | `invalid dynamicNodeFeature "<val>": must match pattern ^[a-zA-Z0-9_-]+$` | `dynamicNodeFeature` violates regex or 64-char limit; job cancelled. |
| `slurmjob_controller.go` | `JobSet completed` \| `JobSet failed` \| `JobSet missing` | Written to Slurm job `Comment` before `SlurmJobReconciler` cancels the Slurm job. |
